# DK 台灣島

把 DK 全台 61 間門市照真實位置蓋在一座 3D 台灣島上。每間店掛著 DK 招牌、周圍是一圈商圈（街道、夜市小攤、路燈、店面），街上有穿 DK 空氣鞋的 DKEC 氣球人在逛街。每間店有自己的玩法（小遊戲、小教室、抽鞋籤、留言板、小白鞋工廠）。

點一間店，鏡頭會降到店門口、開門進店：店長氣球人站在櫃台後面說「店長的一句話」，鞋牆上擺著店長推薦，旁邊是這間店的玩法角落。店長氣球人的圖在 `assets/mascot-*.png`（從空氣鞋小教室的角色圖裁出來的）。

純靜態網頁，不用安裝、不用編譯，可以直接放 GitHub Pages。3D 用 [three.js](https://threejs.org/)（從 jsDelivr 載入）。

## 檔案在哪

```
index.html        網頁本體
css/style.css     介面樣式
js/               程式（平常不用動）
  main.js         讀資料、檢查資料、串起畫面
  world.js        3D 場景、鏡頭、點擊
  islands.js      台灣島的形狀、山、門市排位置、商圈範圍
  buildings.js    各種門市建築與 DK 招牌、熱氣球廣場
  town.js         商圈裡的店面、夜市小攤、路燈
  landmarks.js    台灣景點、機場、離島地標的造型、DK 航空的飛機、DK 物流車
  people.js       門口的店長氣球人、街上逛街的氣球人和他們的鞋
  residents.js    島民角色：造型選項、帽子配件、各種移動模式、照上島天數長大
  postcards.js    島民寄回來的明信片（去哪裡、寫什麼、3D 合照）
  seasons.js      日夜（台灣時間）、節日判斷、節日裝飾
  textrules.js    留言和暱稱的文字限制（擋網址、程式碼、聯絡方式）
  stamps.js       集點蓋章：蓋章紀錄、印章圖案
  ui.js           右側清單、分區卡、進店畫面（含蓋章台）、集章冊、遊戲視窗、登島邀請函、客服任務選單
  service.js      客服任務島各站的內容（到貨推算與物流車送貨畫面、退換貨檢查、打包小遊戲）
assets/           店長氣球人的圖
data/             ← 平常只改這裡
  site.json       網站標題、登島邀請函、集章、彩帶等設定
  regions.json    八個分區（含離島）
  landmarks.json  台灣景點、機場、公廟、DK 電影院
  service.json    客服任務島：四個任務、到貨與退換貨規則、國定假日
  stores.json     61 間門市
  modules.json    玩法（每種玩法的名稱、建築造型、遊戲網址）
  products.json   店長推薦可以選的商品
  picks.json      整理過的店長的一句話＋店長推薦（島上只顯示這份）
  shoppers.json   有買鞋煩惱的路人：可以推薦的鞋、路人的煩惱和答案
  events.json     節日與季節：日期、島上的裝飾、節日帽子、快報上的那句話
apps-script/
  islander.gs     島民證的後端（另一個 Google Apps Script 專案，見「島民證」）
```

每個 json 檔最上面的 `_說明` 寫了各欄位的意思。

## 常見修改

| 想做的事 | 改哪裡 |
|---|---|
| 換某間店的玩法 | `stores.json` 那間店的 `module`，填 `shop`、`balloon`、`downstairs`、`quiz`、`fortune`、`board`、`workshop` 其中一個。島上的建築會跟著換 |
| 店長的一句話、店長推薦 | 店長用「店長的話蒐集」表單填，整理後寫進 `picks.json` 才會上島（見下一節）。要修字，直接改 `picks.json` |
| 加碼推薦商品 | 先在 `products.json` 加商品，再把商品 id 填進 `stores.json` 的 `products`，會排在店長推薦後面 |
| 加一個新玩法 | `modules.json` 加一項：`name`、`building`（用哪種建築造型）、`color`、`desc`、`url`（遊戲網址）、`cta`（按鈕文字）。`url` 留 `null` 會顯示「即將開放」 |
| 新增門市 | `stores.json` 複製一間店改內容。`id` 不能重複；`region` 填分區代號；`latlng` 填經緯度 |
| 調整門市在島上的位置 | 改 `latlng`。在 Google 地圖對門市按右鍵，點第一行的數字就會複製經緯度。位置跟別間店撞到時，會自動挪到旁邊最近的空地 |
| 加一個景點或機場 | `landmarks.json` 加一項：`name`、`latlng`、`model`（造型）、`desc`。點景點會顯示簡介和離它最近的三間 DK。`scale` 可以放大（例如 2 是兩倍大），`featured: true` 的名牌比較大、全景也看得到（目前玉山、阿里山神木） |
| 加一間公廟 | `landmarks.json` 加一項，`type` 填 `temple`、`model` 填 `shrine`、`deity` 填主祀神明。公廟的 `id` 之後遶境路線會用到，不要隨意改 |
| 打開／關掉留言板 | `site.json` 的 `messageBoard`（true／false） |
| 換飛機拖的活動彩帶 | `site.json` 的 `banners`：每一項是 `text`（彩帶上的字）、`url`（點彩帶開的活動頁）、`color`（底色），可以放好幾個，飛機每飛一趟換下一個 |
| 換領優惠券氣球人的連結 | `site.json` 的 `coupon`：`url` 是領券網址，`title`／`desc`／`cta` 是卡片文字，`lapSeconds` 是繞台灣一圈幾秒，`route` 可以自訂巡迴路線。點它鏡頭會一路跟著飛；網址 `…/#coupon` 可以直接打開領券卡片 |
| 下架留言 | 留言送出就直接上牆。不適當的到「店長的話蒐集」試算表的「門市留言」分頁勾「隱藏」 |
| 加禁用字 | 試算表的「禁用字」分頁，A 欄一列一個詞；留言和暱稱含這些字就送不出去 |
| 打開／關掉島民角色 | `site.json` 的 `residents`（true／false），後端在店長表單的 Apps Script（v3 起支援，見下面「島民角色」） |
| 改集點蓋章的規則、優惠券 | `site.json` 的 `stamps`：`goal` 是集滿幾章、`reward` 是集滿後的優惠券（`url` 領券網址、`code` 優惠碼、`cta` 按鈕字）。`enabled` 改 false 就整個關掉（見下面「集點蓋章」） |
| 下架島民 | 試算表的「島民角色」分頁：勾「隱藏暱稱」只拿掉名字；勾「隱藏」整個角色從島上拿掉 |
| 改客服任務島的規則 | `service.json`：`shipping`（幾個工作天到貨、配送提醒、`holidays` 國定假日）、`returns`（檢查清單、退換貨規則、打包步驟、申請步驟）。官網購物說明改了要一起改；`holidays` 每年依人事行政總處行事曆更新。網址 `…/#service` 打開任務選單，`…/#mission/shipping`、`…/#mission/returns` 直達某一站 |
| 開放選鞋研究所、高度探索站 | 內容還沒做；`service.json` 那個任務的 `comingSoon` 目前是 true |
| 改分區名稱、介紹、名牌位置 | `regions.json` |
| 改標題 | `site.json` 的 `title`、`subtitle` |
| 改「幫路人挑鞋」的鞋款、煩惱、優惠券 | `shoppers.json`：`reward` 是挑對送的優惠券；`shoes` 是可以推薦的鞋（填 `salePageId` 就有官網連結和商品圖）、`customers` 是路人的煩惱（`answer` 最適合的鞋、`also` 也算對的鞋）、`slots` 是島上同時有幾個「!」 |
| 改開場的登島邀請函 | `site.json` 的 `invite`：信封上的字、信的內容、亮點清單（`mark` 是圓章裡的字）、署名、登島按鈕。每台裝置第一次來會先看到信封，右上角「?」可以再看一次 |

**改完用 `?debug` 檢查**：在網址後面加 `?debug`（例如 `https://rhk9003.github.io/dk-taiwan-island/?debug`、本機 `http://localhost:8781/?debug`），資料有寫錯（例如玩法代號打錯、商品 id 找不到）時，畫面右下角會出現「資料提醒 N 則」，按 F12 打開 Console 可以看是哪一間店的哪個欄位。一般客人的網址不會看到這個提醒。json 格式錯誤（少逗號、少引號）時整個畫面會顯示錯在哪一個檔案。

## 店長的話：先整理再上島

店長在 https://rhk9003.github.io/dk-store-manager-picks/ 填的內容會存進 Google 試算表，但**原文不會直接上島**：店長常常沒照格式填（只寫型號、兩雙寫在一格、名稱和顏色混在一起、說法跟官網規格不一樣），要先整理成 `data/picks.json` 才顯示。

整理的流程：

1. 跑 `python tools/pull_picks.py`：列出新填或重填、還沒整理的店，店長原文存在 `tools/picks_todo.json`（不會上傳）。
2. 把每一家整理進 `picks.json`：
   - 名牌統一寫成「店長 名字」；
   - 一句話修錯字、標點；
   - 型號到官網搜尋，填正確的商品名、型號、顏色和 `salePageId`（官網商品頁網址最後那串數字，填了就自動有連結和商品圖）；
   - 推薦理由對照官網規格，不正確的說法要改掉。
   - 官網查不到的商品（門市限定款）只填名稱和理由，島上會顯示 DK 鞋盒。
3. `source` 填店長那次的填寫時間。店長之後重填，網址加 `?debug` 會提醒「XX 店長重填了，picks.json 要重新整理」。

試算表暫時讀不到時，島照常運作（只是留言牆讀不到）。

## 集點蓋章

`site.json` 的 `stamps.enabled` 是 true 時：

- 每間門市的櫃台旁有一個蓋章台，按「蓋章！」會蓋上這間店的印章（外圈店名、中間 DK、下面日期，顏色是這間店玩法的顏色）。一間店只能蓋一次。
- 右下角的「集章 n/10」按鈕打開集章冊，看蓋過哪些店；點印章可以回到那間店。還沒集滿時有「帶我去一間還沒蓋的店」。
- 集滿 `goal` 章，集章冊會出現 `reward` 的優惠券：有 `url` 就是領券按鈕，有 `code` 就顯示優惠碼和複製按鈕（兩個都可以填）。都沒填會顯示「優惠券準備中」。
- 花東的熱氣球廣場是「集章兌獎廣場」，點它的卡片也能打開集章冊。蓋過章的店，地圖名牌和右側清單會多一個小紅章。
- 網址 `…/#stamps` 直接打開集章冊。

**蓋章紀錄存在哪裡**：存在客人自己瀏覽器的 localStorage，關掉網頁、關掉瀏覽器、重開機都還在；但換一支手機、換一個瀏覽器、清除瀏覽資料、用無痕模式就會從 0 開始。在 LINE／FB 裡點開是 App 內建的瀏覽器，跟手機的 Safari／Chrome 是分開的。iPhone 的 Safari 超過 7 天沒來島上，可能會被 Safari 自動清掉。

**防作弊**：蓋章紀錄在客人的瀏覽器裡，懂技術的人可以自己改。優惠券建議用官網「每個會員限領一次」的領券頁，`code` 也會出現在網頁原始碼裡，不要放不能外流的優惠碼。

## 留言和暱稱的文字限制

留言牆和島民暱稱都不審核、送出就公開，所以送出前會先檢查。網頁上擋一次（`js/textrules.js`），店長表單的 Apps Script 再用同樣的規則擋一次（網頁可以被繞過，後端才算數）：

- 不能放網址（`http`、`www.`、`xxx.com`、`點com` 這類寫法）
- 不能放程式碼或特殊符號（`< > { } [ ] =`、反斜線、反引號、`script` 等）
- 不能放帳號、email（`@`）或電話、一長串數字（連續 9 個以上）
- 同一個字連續 10 個以上算洗版
- 暱稱不能用「DK、高博士、官方、客服、門市、店長、店員、小編、管理員」等字樣
- **防冒充客服詐騙**：留言不能提到客服、官方、公告、LINE／加賴、微信、私訊、電話、帳戶、扣款、退款、匯款、定期購、信用卡等字（去掉空白標點再比對，「加 賴」「L.I.N.E」也擋得到），也不能留「加 dkcs88」「ID：abc123」這種帳號
- 島上**顯示前**也用同一套規則再過一次：就算有人繞過網頁直接打後端，違規的留言、暱稱也不會出現在島上
- 試算表「禁用字」分頁裡的字（只在後端檢查，清單不會公開）
- 全形字（`ｗｗｗ`、`＜`、`＠`）和看不見的字元也擋得到

漏網的留言或暱稱，到試算表勾「隱藏」就會從島上拿掉。

## 幫路人挑鞋

島上隨時有幾個路人頭上冒出黃色的「!」，代表他有買鞋的煩惱。點他，鏡頭會飛過去、他會停下來，卡片上是他的煩惱和四雙鞋：

- 選對了：他會道謝、說明為什麼適合，附官網商品連結；頭上的「!」變成愛心，接著跑到另一個路人頭上。
- 選錯了：他會說自己最在意什麼，可以再選一次。
- 選到 `also` 裡的鞋也算對，他會補充一句更推薦哪一雙。
- 右下角的黃色「幫路人挑鞋」按鈕會直接飛到有煩惱的路人；登島邀請函上也有黃色任務單（`site.json` invite 裡 `featured: true` 的那一項），按「馬上去幫忙」直接開始。
- **挑對就送優惠券**：`shoppers.json` 的 `reward` 設定幫幾位（`after`）才送、優惠券卡片的字、領券網址 `url` 或優惠碼 `code`。每台裝置只能領一次；`url` 和 `code` 都留空就不送。跟集章一樣存在客人的瀏覽器，懂技術的人可以繞過，建議用官網「每個會員限領一次」的領券頁。
- 幫過幾位路人存在客人自己的瀏覽器。鞋款和煩惱都在 `data/shoppers.json`，加一個煩惱就是在 `customers` 加一項。

## 島民角色

`site.json` 的 `residents` 打開後，右下角會出現「＋ 成為島民」按鈕。訪客可以捏一個自己的氣球人放上島：

- 選身體顏色、帽子、配件、鞋子顏色，再選移動模式（環島、北區、中區、南區、東區、逛商圈、爬山、泳渡日月潭），最後取一個 10 字內的暱稱。卡片上方的 3D 預覽會馬上換上選的造型。
- 移動模式要跟店長表單 Apps Script 的 `RESIDENT_MODES` 一致；新增模式時兩邊都要改，後端「管理部署作業 → 新版本」之後才能存。
- 角色會存進試算表的「島民角色」分頁，一台裝置一個角色，之後再捏會覆蓋舊的。
- 造型和移動模式都是固定選項，暱稱也直接公開，送出後就會出現在島上。不適當的到試算表勾「隱藏暱稱」或「隱藏」。
- 有不適當的角色，勾「隱藏」就會從島上拿掉。
- 網址 `…/#me` 會直接打開捏角色的畫面（已經有角色的話，鏡頭會跟著自己的島民）。
- 點島上任何一個島民（或他的名牌），他會停下來、鏡頭跟過去，卡片是他的名片：長到哪個階段、上島第幾天、怎麼移動、最近從哪裡寄明信片。
- 名片下方是**島民留言板**：別人可以留言給這個島民（文字規則和門市留言一樣，直接公開）。島民的主人在「我的島民」看得到收到的留言，不喜歡的可以按「隱藏」；你也可以到試算表「島民留言」分頁勾「隱藏」。隔天以上回來時，快報會說「有人留言給你的島民」。

### 島民會長大、寄明信片

讓客人偶爾回來也看得到變化，都照真實時間算，不用每天來：

- **長大**：從上島那天起算（試算表「島民角色」的建立時間）。0 天「新島民」小小的 → 3 天「島民」→ 7 天「資深島民」→ 30 天「老島民」留白鬍子 → 60 天「島上耆老」再拄拐杖。島上每個人都看得到別人長多大。階段在 `js/residents.js` 的 `AGE_STAGES` 改。
- **明信片**：上島半天後開始，每 12 小時寄一張，留最新 30 張，在「我的島民」卡片裡看。寄哪裡看移動方式：泳渡日月潭大多寄日月潭、爬山寄山上，北中南東寄那一區的景點（偶爾是廟），環島和逛商圈全島都去。每張是島民站在景點前的 3D 合照，照片裡是寄信那天的樣子，晚上寄的天空是暗的。

### 島民證

換手機、清掉瀏覽器資料、或從官網文章（iframe）和直接開網址分開進來，瀏覽器都會當成新的人。島民證是客人捏島民時**自己取的代號**（先放一組隨機的，可以整個改掉；6～12 個英文字母或數字、至少一個英文字母、不能跟別人重複，不分大小寫），之後在「我的島民」卡片上可以改代號、存成圖片；到另一台裝置打開「我的島民」→「以前捏過島民？輸入島民證接回來」，就會變回原本的島民（長大的進度和明信片都在）。

- 後端是**另一個 Apps Script 專案**（`apps-script/islander.gs`），自己的試算表、自己的排隊，不跟留言、存島民搶。
- 第一次設定：到 script.google.com 新增專案，貼上 `islander.gs` → 選 `setup` 按「執行」（會建立「DK 台灣島 島民證」試算表）→「部署 → 新增部署作業 → 網頁應用程式」，執行身分「我」、存取權「所有人」→ 把網址填到 `site.json` 的 `islanderUrl`。沒填就不會出現島民證。
- 號碼就是鑰匙，島民證試算表不要分享。號碼外流時在那一列勾「停用」；同一台裝置 10 分鐘內猜錯 8 次會先擋。

## 日夜與節日

- **日夜**：照台灣時間，17:30～19:00 慢慢天黑、05:00～06:30 天亮。晚上天空和海變暗、門市窗戶亮燈、燈籠和路燈更亮、滿天星星。
- **節日**：`data/events.json`。每個節日有日期、島上的裝飾（南瓜燈、聖誕樹、紅燈籠、遮陽傘）和大家戴的帽子（巫師帽、聖誕帽，沒戴帽子的島民也會戴）。農曆新年每年日期不同，要每年補下一年的 `dates`。
- **特效**（節日的 `fx`）：`bats` 商圈上空的蝙蝠、`pumpkins` 街上飄浮的南瓜燈、`moon` 畫面左上角的月亮（越晚越亮）、`purpleNight` 夜晚的海偏紫、`costumeTrucks` 物流車蓋上白布變裝（布上剪兩個眼洞，下面露出酒紅色車身和輪子，一看就是正常車子在假扮）。`pumpkinRoofs` 門市的酒紅屋頂換成一顆大南瓜、`halloweenTown` 商圈房子的屋頂和遮雨棚換成南瓜橘、紫、黑、`pumpkinCoupon`「領優惠券」大氣球人的頭換成會發光的南瓜燈、手上的票券也換成萬聖節版。（不放幽靈角色：DK 客群年紀較長，可能會介意。）
- **節日小遊戲**（節日的 `treat`，目前萬聖節「不給糖就搗蛋」）：點門市門口的南瓜燈會進店，店裡敲南瓜燈拿一顆糖，集滿 `goal` 間不同門市的糖送優惠券（`reward` 填 url 或 code）。紀錄存在客人的瀏覽器，每個節日每年一份；右下角南瓜按鈕看進度，網址 `#treat` 直接打開糖果袋。
- 測試：網址加 `?time=21` 看晚上 9 點的島、`?event=christmas` 直接看某個節日，兩個可以一起用（`?time=18&event=lunar-new-year`）。

## 島嶼快報

客人隔一天以上回來時，先跳一張「島嶼快報」，列出不在時島上變了什麼：自己的島民長到哪個階段、寄來幾張新明信片、島上多了幾位新島民、蓋過章的店有沒有新留言、現在是什麼節日。沒有任何一項就不跳；客人已經點去別的地方也不跳。網址加 `?report` 隨時看得到（測試用）。

## 直接連到某間店或某一區

網址後面加 `#store/門市id` 或 `#region/分區id`，例如：

- `…/dk-taiwan-island/#store/頂好`
- `…/dk-taiwan-island/#region/kaoping`

可以放在 LINE、門市 QR code 或官網文章裡。

## 在自己電腦上看

直接雙擊 `index.html` 會讀不到資料（瀏覽器的安全限制），要開一個本機伺服器：

```bash
python -m http.server 8781 --directory dk-taiwan-island
```

然後打開 http://localhost:8781 。

## 放上 GitHub Pages、嵌進官網

1. 在 GitHub 建一個 repo（例如 `dk-taiwan-island`），把這個資料夾的內容推上去。
2. repo 的 Settings → Pages → Branch 選 `main`、資料夾選 `/ (root)`。
3. 一兩分鐘後網址會是 `https://rhk9003.github.io/dk-taiwan-island/`。
4. 跟其他小遊戲一樣，在官網文章用 iframe 嵌入：

```html
<iframe src="https://rhk9003.github.io/dk-taiwan-island/" style="width:100%;height:80vh;border:0;border-radius:16px" allow="fullscreen" loading="lazy"></iframe>
```

之後只要改 `data/` 裡的檔案再推上去，網站就會更新，不用重新嵌入。

想讓「離我最近的門市」在官網文章裡也能定位，iframe 的 `allow` 要加 `geolocation`（`allow="fullscreen; geolocation"`）；沒加的話按了會提示客人改用搜尋縣市。

**貼到 LINE 的預覽圖**是 `assets/og.jpg`（`index.html` 的 og: 標籤）。島的樣子大改時，本機開 `tools/og.html`（會跳過邀請函進島）截圖再合成；換網域時 og:url、og:image 的網址要跟著改。

**改了程式（`js/`、`css/`）再推之前**，先跑 `python tools/bump_version.py`：它會把 `index.html` 裡的 js、css 網址換上新的版本號。GitHub Pages 會讓瀏覽器把 js、css 留 10 分鐘，沒換版本號的話，剛更新時客人可能拿到「舊程式＋新資料」，畫面會少東西（例如開場邀請函不出現）。只改 `data/` 不用跑。

## 中央山脈伸展台（穿搭照）

「整個中央山脈就是我的伸展台」：客人上傳穿 DK 鞋的穿搭照，審核通過就掛上中央山脈，票數越高掛越高，第一名在玉山頂。入口在玉山頂的相框、找門市清單上方的綠色橫幅、登島邀請函，也可以直接連 `…/#runway`。

- 後端是獨立的 Apps Script 專案「DK 台灣島 伸展台」（`apps-script/runway.gs`），照片存在 Google Drive「DK 台灣島 伸展台照片」資料夾，試算表「DK 台灣島 伸展台」一張照片一列、「投票紀錄」分頁記每一票。網址填在 `data/site.json` 的 `runway.url`，留空就整個不出現。
- **照片一律先審再上牆**：用審核頁看照片、按「通過」或「不通過」（照片裡要看得到 DK 的鞋）。審核頁網址在 Apps Script 編輯器選 `adminLink` 執行就會印出來（印出來的是 /dev 網址，把 `/dev` 換成正式部署的 `/exec` 也可以）；網址就是鑰匙，不要外流，外流時執行 `resetAdminKey` 換一把。也可以直接在試算表勾「通過」「隱藏」。
- 照片在手機上先縮到 1080 像素再上傳，同時去掉拍照地點（GPS）等資訊；每人最多 3 張、每天每張照片 1 票（後端也擋，每台裝置一天最多 50 票）。暱稱、穿哪雙、一句話用跟留言一樣的文字規則。
- 卡片上的說明文字、規則、同意條款在 `site.json` 的 `runway`。

## 成效追蹤

- 連到官網（dk-shoes.com.tw）的連結，客人點下去時會自動補上 UTM：`utm_source=dk_taiwan_island`、`utm_medium=referral`、`utm_campaign=dk_taiwan_island`、`utm_content=客人當時在哪`（例如 `store-頂好`、`stamps`、`banner`）。在官網 GA4 看「工作階段來源／媒介」= `dk_taiwan_island / referral`，就是台灣島帶過去的流量和訂單。
- `data/site.json` 的 `analytics` 填 GA4 評估 ID（`G-` 開頭）或 Meta 像素 ID 才會載入追蹤碼、送事件：`select_content`（進店、看分區…）、`stamp_get`、`reward_claim`、`module_play`、`message_post`、`resident_save`、`find_nearby`、`outbound_click`。留空就只加 UTM。
- 網址加 `?debug`，按 F12 的 Console 會印出每個事件，方便檢查。

## 手機效能

觸控螢幕或核心、記憶體少的裝置會自動關陰影、解析度最多 1.5 倍（全景每格畫面的 draw call 從約 3,700 降到約 2,000）。電腦上網址加 `?lite` 可以看手機版的畫質。

## 門市營業時間

`data/stores.json` 每間店的 `hours` 是從官網門市資料抓的（平日 `weekday`、週末 `weekend`）。門市改營業時間或開新店時跑 `python tools/pull_hours.py` 就會更新。進店畫面最下面會顯示「營業中／已打烊」（台灣時間，國定假日沒另外算）。
